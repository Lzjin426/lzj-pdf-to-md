# 混合模式：逐页双向核对

本参考只用于用户选择的混合模式。目标是在原 PDF 页面与最终 Markdown 之间建立有证据的对应关系，不是只检查有无关键词或让 AI 凭上下文复述。

## 准备页面与定位

1. 在独立任务目录保留只读的原始 Markdown、内容列表 JSON 和图片；另建待修订的工作副本。检查输出来自本次任务，不能复用旧结果。取得 PDF 的物理页数，分别记录用户要求处理的页码范围与页面上印刷的页码，它们可能不同。
2. 用可用工具将每个目标物理页渲染为图片。先使用能看清正文的分辨率；小字、公式、表格或工程图需要时放大或另行局部截取。实际用视觉工具打开每一页；只运行渲染命令、读取 OCR 文字或 JSON 不等于看过页面。
3. 优先用内容列表的 `page_idx`、文字和图片路径辅助寻找 Markdown 片段，检查 JSON 文件、结构、空数组、空正文块及异常引用。页码通常从零开始，但不能假定它一定对应原 PDF 物理页：有的服务或选页方式可能重新编号。用多页内容与原图核实基准；例如一次 3–7 页的实测结果是 0–4，而不是 2–6。不连续选页、其他 CLI/服务版本和空页必须根据实际证据另行判断。
4. 跨页段落、表格、脚注和图注可能被合并，不能只按单个 `page_idx` 分割。对照上下页，并确认合并后的 Markdown 没有漏行、错列、重复或错序。JSON 缺失、为空、块无法定位时，以实际页面和完整 Markdown 人工定位；仍无法核实则登记未验证，不能把该页标作完成。

## 分工与逐页检查

主控根据页数和内容复杂度按连续物理页分组，提供每组两侧必要的相邻页、原始 Markdown、内容列表、图片目录、用户要求及页码/页眉页脚/脚注的清理规则。通常同时启动 2–3 名只读检查者，长文档分批处理，按环境和文件复杂度调整；避免多个 agent 同时修改共享文件。单页文档可按区域或两个核对方向分工；没有 agent team 时先向用户说明并询问是否改为顺序检查。每个检查者必须亲自打开并查看负责范围的每页图片及实际 Markdown，不以主控结论或 JSON 代替原文。

每个目标物理页至少执行并记录：

1. **PDF → Markdown**：正文、标题、数字和单位、上下标、公式及编号、表格的行列与合并关系、原图、图表文字和图注、引用、脚注、可见页眉页脚等是否存在且对应。按已确定的规则区分有意清理的杂项与遗漏；有实质内容的脚注不能因属于脚注而自动删除。关注扫描噪声、两栏顺序和跨页边界。实际打开 Markdown 引用的图片，与原页比较边界及图内文字：文件存在不代表图片完整，可能被裁切。检查公式的实际表达含义和可能的显示问题，数字或变量被拆成单字符时不能只看出现在源码里。
2. **Markdown → PDF**：该页关联的每个 Markdown 片段是否能在原图或相邻跨页内容找到；检查多出的内容、重复、错置、错误归页、错图及数字公式被改写。图表保留为图片不等于已提取图内数据，不自行编造。
3. 记录物理页码、实际查看的页面或区域、对应的 Markdown 内容位置、两方向的状态，以及每处问题的原文依据、现有内容、建议修正和不确定性。没有问题也记录已查看的证据；只因未发现问题不填虚构位置。

按页分组时，相邻范围可共享上下文页，但每个目标页有唯一主责任人；按方向或区域分工时，主控需核对两方向和全部区域均有负责人。跨界问题交主控统一处理。空白页也需确认其确为空白。看不清的内容在放大后仍不确定时标为待确认，不根据上下文猜测。

## 合并、复核与覆盖

主控收集各组结果，按原 PDF 修复能确认的错漏，保护原始 CLI 副本和图片。缺失或裁切的图可从原 PDF 以足够分辨率重新截取，检查图的边界与可读性，另存到成品图片目录并更新相对链接；应保留但缺失的脚注按原文补回。对不能准确还原的局部保留原图或原样，并明确报告。不要把说明、猜测或审查标记混入原文，除非用户明确要求。

完成修正后，重新查看每处改动对应的原页与 Markdown，跨页内容同时核对相邻页。对最终 Markdown 从头到尾做反向覆盖：每个正文、公式、表格、图片和引用片段都能定位到原文或标记为未验证；注意新增修正、跨页块及未分配的内容。核对图片引用与文件是否存在。

工作记录至少包含目标物理页全集、每页实际视觉核对与两个方向的状态、对应 Markdown 位置、已确定的杂项清理规则、问题与处置、待确认项和反向未覆盖内容。不得把空白页、被跳过页、截图未打开页或只有 JSON 的页记成已视觉核对。无法证明全部目标页和应保留的 Markdown 内容均已覆盖，或仍有未验证片段、关键内容辨认不清时，交付时明确列出缺口，不宣称全文完整核实。任务中断保留可恢复记录；完成交付后按主技能的临时文件规则清理。
